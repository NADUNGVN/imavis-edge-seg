# QAT v1 (Contribution 6) — 2026-09-13

Implemented `src/imavis_edge_seg/training/quantization.py`: dynamic per-tensor
symmetric INT8 fake quantization (`torch.fake_quantize_per_tensor_affine`, built-in
straight-through gradient estimator), and `QATConv2d`/`apply_qat` to convert an
existing model's plain `nn.Conv2d` layers in place.

## Key design decision: state_dict compatibility, not just wrapping

The first implementation wrapped each `nn.Conv2d` as a submodule (`self.conv =
conv`), which silently changed every affected parameter's `state_dict` key (e.g.
`"0.weight"` -> `"0.conv.weight"`) — caught before landing by writing a test for it
(`test_qatconv2d_preserves_state_dict_keys_and_values`) rather than assuming the
wrapper was transparent. Fixed by making `QATConv2d` *subclass* `nn.Conv2d` directly
and take over the original's `weight`/`bias` `Parameter` objects, so a converted
model's `state_dict` is byte-identical in key names to the original's. This is the
property `RESEARCH_PLAN.md` §5.2's workflow ("FP32 teacher -> shared supernet -> QAT
INT8") actually needs: an FP32 checkpoint must load into a QAT-converted model of the
same architecture (to *start* QAT from FP32 weights) and vice versa. Verified with a
real load_state_dict round trip test, not just a key-name comparison.

9/9 new tests pass (92/92 total): zero-tensor edge case, bounded quantization error,
straight-through gradient flow, more bits = less error, state_dict preservation,
forward/backward shape and gradient-finiteness, idempotent double-`apply_qat` safety,
recursion into nested modules, and the FP32-checkpoint-compatibility round trip.
Verified end to end against the real `fast_scnn` baseline architecture: all 44
`nn.Conv2d` layers convert cleanly, forward/backward both work at a realistic
256x512 resolution.

## Explicit scope limits (documented in the module, not hidden)

- **Dynamic, not calibrated, quantization range**: the fake-quant scale is recomputed
  from each forward call's own observed min/max, not a running-average observer
  fit on a calibration set. This is a real simplification vs. production QAT --
  any INT8 accuracy number from this module should be read as an optimistic upper
  bound, not a final paper number, until proper calibration (§5.2: "calibration set
  must represent day/night/rain/fog/snow") is added.
- **Targets the baseline architectures only** (`models/baseline_architectures.py`,
  plain `nn.Conv2d`), not yet the supernet's `SlimmableConv2d`
  (`models/blocks.py`) -- the supernet's per-level active-channel slicing and
  per-level `SlimmableBatchNorm2d` need their own quantization-range handling
  (e.g. does "tiny"'s 25%-width slice share a quantization range with "large"'s
  full width, or get its own?), which is a real design question, not yet answered
  or implemented.
- No actual QAT *training run* has happened yet -- this is the mechanism, not a
  result. The §11 go bar ("INT8-QAT loses <=~1.0-1.5 mIoU vs. FP32") cannot be
  evaluated until a real training run (ideally resuming from an existing FP32
  checkpoint via `training/checkpoint.py`'s resume support, then continuing with
  `apply_qat` applied) is done and evaluated.

## Not yet done

- No training script/CLI wiring (`scripts/train_baseline.py`/`train_supernet.py`

- No calibrated (real-data) quantization ranges.
- No supernet (`SlimmableConv2d`) support.
- No actual FP32-vs-INT8 mIoU comparison run yet.
